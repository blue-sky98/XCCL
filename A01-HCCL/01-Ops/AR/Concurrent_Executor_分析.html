并发执行时序图（核心：双模板同时运行）
Concurrent 6 个同步点
OrchestrateLoop 中，模板间前同步后，temp0（threads_[0..3]）和 temp1（threads_[4]）同时并发执行， 各自完成 KernelRun 后通过模板间尾同步汇合。这是 Concurrent Executor 区别于 Sequence（串行）和 OmniPipe（流水线）的核心特征。
关键区别：
• Sequence Executor：4 模板串行（Intra RS → Inter RS → Inter AG → Intra AG），总时间 = 各步之和
• OmniPipe Executor：三级流水线（切 chunk 流水），有填充/排空开销
• Concurrent Executor：2 模板完全并发，总时间 ≈ max(temp0时间, temp1时间)，通过带宽比例分配使两路同时完成

带宽比例 11:10 的原因
11:10 = (物理带宽 × 算法效率)_mesh : (物理带宽 × 算法效率)_clos， 是物理带宽差异与算法效率差异的综合结果。
维度Mesh (temp0)CLOS/NHR (temp1)谁占优
物理带宽Mesh 直连 UBC，带宽高CLOS 交换 UBC，经交换芯片Mesh 略高
算法并行度3 路从线程并行 SendRecv1 路串行（channelsPerRank=1）Mesh 略高
Reduce 方式需额外 3 次 LocalReduce边收边算（SendRecvBatchWriteReduce）NHR 找回一点
拷贝开销无 PreCopy/PostCopy（仅 2 次 LocalCopy）有 PreCopy + PostCopy（各 0.476 ds）NHR 找回一点
综合净效率≈ 11≈ 10接近 1:1
优化目标：data_mesh / BW_mesh = data_clos / BW_clos → 两路同时完成。
按 11:10 分配数据量（0.524 ds : 0.476 ds），使得 temp0 和 temp1 的执行时间大致相等， 并发执行时不会出现一路等待另一路的情况，最大化整体吞吐。

CCU_MS 模式差异：Mesh 硬件双流 → 11×2=22, CLOS 不变=10 → 比例变为 22:10， 此时 Mesh 分配更多数据（约 0.688 ds），NHR 分配更少（约 0.312 ds）。
